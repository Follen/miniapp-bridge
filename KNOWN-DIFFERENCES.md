# Known Differences

| Area | Current status | Technical reason | Required validation |
|---|---|---|---|
| Native packaging | The Go binary loads project `miniapp-frida.dll`, which statically contains official frida-core 17.3.2, instead of linking the 322 MB MSVC archive directly from MinGW cgo | Go's Windows cgo linker uses MinGW ABI; the official devkit is an MSVC static archive. The opaque shim is required for a stable ABI. | `scripts/build-frida-shim.ps1`; native lifecycle and reattach test pass |
| Fixed-port live WMPF/CDP | No known difference in the Windows link-smoke path. The launched bridge owns both fixed listeners, attaches the real target, accepts the WMPF upstream, and proxies the three baseline commands. | The historical link smoke passed, but it proves transport only. | Re-run link smoke against the final build and future address tables. |
| Live DevTools command matrix | No remaining known command-matrix difference for the tested Windows 25297 environment. | The final matrix covers Runtime, Debugger, Page, DOM, Network, Console, Performance, object, exception, pause/resume, call-frame, long-message, concurrent, error, context, and reconnect flows. | Final live run returned `reconnect=true events=371`; repeat for each newly supported WMPF version. |
| Windows smoke shutdown | No reference protocol difference. The smoke harness must not terminate the bridge abruptly because that bypasses the same ordered cleanup used in normal operation. | A dedicated process-group runner sends `CTRL_BREAK_EVENT`, waits for bridge exit code 0, fails on force fallback, verifies both ports are released, and checks the upstream peer survives. | Final live run returned `target-survives-shutdown=true peer=66620` and `ports-released=true`. |
| Non-Windows zlib fallback | Windows+cgo uses pinned zlib 1.3.1 and matches reference deflate bytes exactly. Other platforms currently use Go `compress/zlib`, which is wire-compatible but can emit different compressed bytes. | Windows is the first supported platform; the platform abstraction keeps the fallback buildable while an exact native zlib package is added per future platform. | Run `TestReferenceCodexDebugObjectAndCompression` on each newly supported platform before claiming byte-exact parity there. |
| Runtime shutdown entry point | `frida_deinit()` is exposed as an explicit final runtime shutdown after all device/session/script owners are released; it is not called on every device close because the pinned Windows devkit cannot reinitialize safely between sequential device lifetimes. | The shim keeps device close and process-wide Frida runtime shutdown as separate ownership layers. | Exercise CLI signal shutdown and a subsequent process start; do not call `ShutdownRuntime` while another device is live. |
| `jscontext_id` extension | The fixed reference proxy sends an empty `jscontext_id`; this port routes the selected `jscontextId` as required by the complete-parity specification. | Context discovery/selection/routing is an explicit Go responsibility in the requested behavior contract. | Compare a live multi-context target when additional upstream contexts are available. |
| Protobuf.js malformed length-delimited tolerance | The pinned protobuf.js decoder accepts one historical `120501` truncated-string fixture and returns a one-byte payload; Go's decoder returns `io.ErrUnexpectedEOF` for the same malformed frame. | Go keeps strict frame-boundary validation so corrupt input cannot leak arbitrary trailing bytes; all valid, unknown-wire and other corrupt fixtures match exactly. | Keep the differential fixture and require no panic/process crash; revisit only if byte-for-byte malformed-frame compatibility becomes mandatory. |
